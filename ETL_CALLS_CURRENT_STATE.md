## Critical Gaps

### Gap 1: No Transcript Persistence ⚠️ BLOCKING

**Current flow:**
```
Fireflies API → short_summary → calls table
```

**What's needed:**
```
Fireflies API → utterances → call_transcripts table
                           → assembled transcript
                           → conversation metrics
                           → summary (derived)
                           → calls table
```

**Missing modules:**
- `transcript_store.py` (fetch_utterances, build_transcript_row)
- `sb.bulk_upsert_transcripts()` storage method

**Why blocking:**
- Migration 030 created `call_transcripts` table
- Migration 031 added metrics columns
- ETL can't populate either
- Downstream features depend on this data

### Gap 2: No Rate-Limit Backoff ⚠️ HIGH IMPACT

**Problem:**
Fireflies GraphQL API returns throttling in **response body**, not HTTP status:

```json
{
  "data": null,
  "errors": [{
    "message": "Rate limit exceeded. Please try again later."
  }]
}
```

**Template's exception handler:**
```python
except Exception as e:  # Only catches HTTP exceptions
    print(f"   ✗ Error fetching {platform_name} calls: {e}")
    break
```

**Never fires because:**
- HTTP request succeeds (200 OK)
- Error is in JSON body
- Template never checks body for errors
- No retry happens

**GrowthBook's experience:**
- "This failed 1,920 of 2,189 calls before it was caught"
- 88% failure rate
- Went unnoticed because errors didn't surface

**What's needed:**
- Parse GraphQL response body for errors
- Detect rate limit messages
- Implement exponential backoff (1s, 2s, 4s, 8s...)
- Retry with jitter

### Gap 3: No Multi-Source Dedup ⚠️ FEATURE GAP

**Current:**

**GrowthBook:**

**Real client setup:**

- Same call analyzed twice
- Wasted API calls and tokens

## Summary

**Template's etl_calls.py is a summary-only ETL:**
- Fetches call metadata + summaries
- Writes to `calls` table
- Does NOT fetch or store transcripts
- Single source only (no multi-source dedup)
- No rate-limit handling (88% failure in GrowthBook before fix)

**To reach parity with GrowthBook, needs:**
1. **transcript_store.py** module (fetch_utterances, build_transcript_row)

4. **GraphQL error parsing** (detect throttling in body)
5. **Exponential backoff** (retry with jitter)
6. **Multi-source config** (get_call_sources plural)
7. **Source-priority dedup** (Fireflies > Gong > Apollo)
8. **Logging infrastructure** (diagnostic output)
9. **Timezone utilities** (reporting TZ conversion)
10. **LLM client wrapper** (retry/error handling)
